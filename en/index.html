PROPRIETARY OPTREE ENGINE

The whole scene first.
More detail where it matters.

Optree is our core engine for lightweight visualization and web-based streaming of point clouds spanning tens of gigabytes. It organizes data by spatial region and level of detail, progressively delivering the 3D data needed for the current view.

VIEW-ADAPTIVE DETAIL

Select the detail the view needs.

Level of Detail (LOD) selects the appropriate amount of data for the screen. An overview appears first; zooming or changing the viewpoint brings in additional points for the relevant regions.

  • A hierarchy separating spatial regions from detail layers
  • Data selection guided by visible regions, zoom and available resources

PROGRESSIVE 3D STREAMING

Receive 3D data and render it directly.

Required coordinates and colors arrive without downloading the entire source file first. Browser and desktop viewers render them on the GPU, retaining the current geometry while new detail becomes ready.

  • Progressive point-data transfer, decoding and GPU upload
  • Cache reuse and off-screen data cleanup for memory management

The server manages source and hierarchy data.

Source point clouds such as E57 and PLY are prepared as spatial hierarchies and rendering data. Clients request regions through a common LOD node interface; source management and data preparation remain on the server.

Delivery adapts to the view and resources.

Camera direction, projected size and the point budget guide data selection. Navigation takes priority during movement, followed by refinement when the view settles. Network, decoding and GPU memory constraints also inform the plan.

The client maintains visual continuity.

Background workers decode data for incremental GPU uploads. The existing view stays in place until new data is ready. Cancellation and view changes clean up unnecessary resources and reject late responses from earlier work.

Displayed points stay linked to the source.

Source point identifiers connect selections and labels to the original data. Labels and edit states are managed separately from source and LOD data, connecting exploration to subsequent analysis and workflow tools.
